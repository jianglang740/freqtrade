# FibMartingaleStrategy — 斐波那契马丁格尔策略说明文档

> 短线双向合约马丁策略，ZigZag 波段识别 + 斐波那契回撤 + DCA 加仓。固定止盈，总保证金 -25% 硬止损。

**结论先行：** 2026-01 至 2026-10 的 10 个月回测，按「总保证金 -25%」严格执行止损后，策略亏损 **-75.81%**，最大回撤 **87.69%**。旧版文档里的 +45% 依赖的是 DCA 连补和止损不跟随加仓均价这两个旧行为，不能作为可实盘的收益预期。限制加仓深度后在 2026 窗口能修回 +20.59%，但同样的配置在 2024 / 2025 两个样本外窗口分别亏 **-96.45% / -96.02%**——没有优势，只有窗口运气。

---

## 一、策略哲学

**核心理念：** ZigZag 找到真波段，在斐波那契回撤位开仓，逆向加仓，达到固定止盈就走。

**适用场景：**

- 1 分钟 K 线短线操作
- 震荡市中的马丁交易
- 主动提取利润的资金管理（赚钱后定期提走）

**不适用场景：**

- 强单边趋势行情
- 永续运行不提取利润
- 不能接受「单笔亏损吃掉多笔盈利」的资金曲线

## 二、当前参数

### 2.1 基础

| 参数                        | 值        | 说明                                   |
| --------------------------- | --------- | -------------------------------------- |
| `timeframe`               | `"1m"`  | 1 分钟 K 线                            |
| `can_short`               | `True`  | 做多 + 做空                            |
| `startup_candle_count`    | `250`   | 预热 250 根（4 小时）                  |
| `process_only_new_candles` | `False` | K 线中途也重算信号（关键修复，见 6.1） |
| `leverage_value`          | `10`    | 全仓 10 倍                             |

### 2.2 仓位

| 参数                              | 值       | 说明                    |
| --------------------------------- | -------- | ----------------------- |
| `position_adjustment_enable`    | `True` | 允许 DCA                |
| `max_entry_position_adjustment` | `7`    | 首仓 + 最多 7 档 = 8 层 |
| `max_open_trades`               | `14`   | 配置值；只有 2 个 pair，实际最多 2 个仓位 |

### 2.3 止盈止损（两条线）

| 参数                 | 值              | 10 倍杠杆下                            |
| -------------------- | --------------- | -------------------------------------- |
| `minimal_roi`      | `{"0": 0.15}` | 保证金 +15%（价格 +1.5%）止盈          |
| `hard_stop_margin` | `0.25`        | 保证金 -25%（价格从**当前均价**反向 2.5%） |
| `stoploss`         | `-0.8`        | 框架兜底，价格反向 8%，接近爆仓价      |

**为什么硬止损在 `custom_exit` 而不是 `custom_stoploss`：** freqtrade 的止损「只上不下」，加仓成交后 `recalc_trade_from_orders()` 又会用上一档的止损百分比把止损重新锚到新均价，且不允许 refresh，方向恰好是把止损顶回去。实测 7 次加仓后，名义上跟随均价的止损实际卡在约 -14% 保证金。`custom_exit` 用 `current_profit`（分母是当前总保证金，含全部加仓，且已含杠杆和手续费）判断 `<= -0.25`，才是真正的「总保证金 -25%」，多空对称。代价是按每次 `should_exit` 的当前价判断，不是盘中逐笔，极端插针会多亏一点（实测单笔最差 -39.6%）。

### 2.4 波段识别

| 参数                 | 值        | 说明                                |
| -------------------- | --------- | ----------------------------------- |
| `zigzag_threshold` | `0.020` | 价格从极点回撤/反弹 2.0% 才确认拐点 |

ZigZag 是逐根 K 线的状态机，没有固定窗口：只用当前及过去的 K 线，任何时刻保证 `zz_high >= zz_low`。

### 2.5 斐波那契与马丁

| 参数                    | 值                                                       |
| ----------------------- | -------------------------------------------------------- |
| `fib_levels`          | `[0.382, 0.5, 0.618, 0.786, 0.886, 1.0, 1.272, 1.618]` |
| `martingale_mults`    | `[1.0, 1.5, 2.5, 4.0, 6.0, 8.0, 11.0, 13.0]`           |
| `entry_fib_threshold` | `0.382`                                                |
| `base_contracts`      | `BTC: 0.01, ETH: 0.15`                                 |

## 三、信号链路

### 3.1 ZigZag 波段确认

逐 K 线维护「已确认」和「本段潜在」两个极值：

- 上升段：高点继续抬高，收盘从高点回撤 > 2.0% 才确认真波段顶并转入下降段
- 下降段：低点继续降低，收盘从低点反弹 > 2.0% 才确认真波段底并转入上升段
- 输出 `zz_high = max(已确认高点, 本段潜在高点)`、`zz_low = min(已确认低点, 本段潜在低点)`

这样既不会出现 `zz_low > zz_high` 的反向区间，也不会在单边趋势里把区间卡死在 0。

**阈值不宜过小。** 阈值越低确认越频繁 → fib 线跳动越快 → 价格来不及走到交叉位线就漂走，信号反而更少。

### 3.2 入场

- 做多：收盘价从上方跌破 `fib_dn_382`
- 做空：收盘价从下方涨破 `fib_up_382`
- 波段幅度 > ZigZag 阈值才允许入场

### 3.3 DCA 加仓

`confirm_trade_entry` 在入场瞬间锁定当前 ZigZag 极值，存入 `_pending_locks`（按 pair + 方向），首次调用 `adjust_trade_position` 时转移到 `_locked_swings`。之后所有加仓档位都用这份锁定值，不随行情漂移。

```
做多：fib_dn_500 → 1.5x, fib_dn_618 → 2.5x, fib_dn_786 → 4.0x ...
做空：fib_up_xxx → 镜像
```

本轮修复的护栏：

- 必须看到上一档价格真正穿越 fib 线才加仓（用上一次调用的价格做交叉判断），不会连续补仓
- 每根 1m K 线最多加一档
- 有挂单时不再重复提交
- 加仓基数取首仓订单的实际成交量，而不是理论值
- 当前保证金亏损已达 -25%，或加仓后的新均价已经处于 -25%，都拒绝加仓

### 3.4 退出

```
1. custom_exit  hard_stop_margin_25pct  ← 总保证金 -25%，按当前均价实时判断
2. minimal_roi  0.15                    ← 保证金 +15% 固定止盈
3. custom_exit  timeout_30d             ← 持仓 > 30 天不盈利强制退出
4. stoploss     -0.8                    ← 框架兜底，只防灾难
```

没有追踪止损。

## 四、最新回测结果（2026-01-01 → 2026-10-31，304 天）

> 订单类型：市价单。1m K 线，BTC/ETH 永续，全仓 10x，手续费 0.05%，初始资金 5000 USDT，首仓 200 USDT。

### 4.1 总览

| 指标           | 数值                          |
| -------------- | ----------------------------- |
| 交易总数       | 540                           |
| 胜率           | 83.9%（453 赢 / 87 输）       |
| 总收益         | **-75.81%（-3,790 USDT）** |
| 最大回撤       | **87.69%（-5,612 USDT）** |
| 回撤区间       | 2026-01-31 → 2026-07-14（164 天） |
| 盈亏比（PF）   | 0.862                         |
| Sharpe         | -1.40                         |
| Sortino        | -1.16                         |
| CAGR           | -81.9%                        |

净值从 2026-01-31 的 6,399 USDT（+28%）一路跌到 2026-07-14 的 787 USDT，之后才回升到 1,210 USDT。

### 4.2 退出结构

| 退出方式              | 笔数 | 平均每笔  | 总贡献          |
| --------------------- | :--: | --------- | --------------- |
| ROI 止盈（+15%）      | 453  | +$52    | +$23,683        |
| 总保证金 -25% 硬止损  |  85  | -$323   | -$27,467        |
| 超时 / 强平           |   2  | -$3     | -$6             |
| **净合计**      | 540  |           | **-$3,790** |

**输家仓位远大于赢家：** ROI 赢家平均只加仓 2.98 档，硬止损输家平均 6.07 档；被硬止损的 85 笔平均投入保证金 1,236 USDT，而全部交易平均只有 488 USDT。这是马丁结构的固有代价，也是亏损的主因。

### 4.3 多空拆分

| 方向 | 笔数 | 胜率  | 盈亏             |
| ---- | :--: | ----- | ---------------- |
| 做多 | 234  | 81.2% | **-$5,918** |
| 做空 | 306  | 85.9% | +$2,127          |

10 个月里 BTC 整体下跌，做空勉强为正，做多被硬止损反复打掉。

### 4.4 与旧版本的对照

| 版本                                                    | 交易 | 总收益      | 最大回撤 | 胜率  |
| ------------------------------------------------------- | :--: | ----------- | -------- | ----- |
| A 旧代码：止损锚在首仓，**不随加仓均价下移**           | 694  | **+55.46%** | 35.49%   | 68.9% |
| B 中间态：止损想跟随均价，但被框架重新锚定顶回（约 -14%） | 639  | -25.33%     | 68.63%   | 78.2% |
| C 当前版本：`custom_exit` 严格 -25% 总保证金            | 540  | **-75.81%** | 87.69%   | 83.9% |

B 和 C 是同一套信号，只改止损语义。差距说明：**策略的正收益完全依赖「深档仓位不设紧止损」。** 一旦按用户要求把止损固定在总保证金 -25%，深档仓位会被反复截断，胜率升到 84% 也救不回期望。

### 4.5 核心洞察

- 单笔期望为负：赢家 +$52，输家 -$323，需要 6.2 笔赢家才能抵 1 笔输家，实际胜率 5.2:1，差一点。
- 加仓到 6-8 档的仓位是亏损来源（8 档 20 笔、7 档 48 笔、6 档 62 笔）。
- 提高胜率的唯一办法是放宽止损，而这正是旧版本「看起来赚钱」的原因，不是策略有优势。
- **当前形态不建议实盘。**

### 4.6 参数优化尝试与样本外检验

方向：深档是唯一的大额亏损来源（输家平均 6 档、投入 1,200+；赢家不到 3 档），所以只砍尾部仓位，不动信号。

同一窗口（2026-01 ~ 2026-10）的参数对照：

| 配置                       | 总收益      | 最大回撤 | PF    | 做多     | 做空     |
| -------------------------- | ----------- | -------- | ----- | -------- | -------- |
| 8 层原倍率                 | -75.81%     | 87.7%    | 0.862 | -5,918   | +2,127   |
| 最多 3 层                  | -11.92%     | 32.5%    | 0.957 | -1,792   | +1,196   |
| 最多 4 层                  | -10.99%     | 53.9%    | 0.971 | -2,174   | +1,624   |
| 最多 5 层                  | **+20.59%** | 51.1%    | 1.043 | -2,281   | +3,310   |
| 8 层、尾部倍率封顶 5x      | +5.67%      | 48.3%    | 1.012 | -3,244   | +3,528   |

3→4→5 层不单调，最好的 PF 也只有 1.043，回撤仍在 50% 左右，已属可疑。于是用两个开发时没看过的窗口做样本外检验：

| 配置          | 2026-01~10（调参窗口） | 2024-01~10（样本外） | 2025-01~10（样本外） |
| ------------- | ---------------------- | -------------------- | -------------------- |
| 8 层原倍率    | -75.81%                | **-97.14%**    | **-96.31%**    |
| 最多 5 层     | +20.59%                | **-96.45%**    | **-96.02%**    |

结论：**+20.59% 是窗口噪声，不是可复现的优势。** 两种参数在 2024 / 2025 都把账户打到接近归零，方向完全一致。限制加仓深度只能压缩同一窗口内的尾部亏损，不能创造期望——马丁的期望由「+15% 的小赢 × 高胜率」和「-25% 的大亏 × 低胜率」决定，后者永远更大。

## 六、已知问题与修复

| 问题                          | 原因                                                         | 修复                                              |
| ----------------------------- | ------------------------------------------------------------ | ------------------------------------------------- |
| ZigZag 区间反向 / 卡在 0      | 用潜在极点直接覆盖已确认极点                                 | 改为 `max/min(已确认, 潜在)`，并加单元测试        |
| 一次行情补多档                | 只看当前价是否在 fib 线外，不判断穿越                         | 用上一次调用价做交叉判断 + 每根 1m 最多一档       |
| 加仓量错位                    | 用理论手数而非首仓实际成交量                                 | 取首笔入场订单的 `safe_amount_after_fee`        |
| 状态跨交易串味                | 状态挂在实例上但没有清理                                     | 按 `trade.id` 存，全平后 `order_filled` 清理    |
| 止损「跟随均价」无效          | `recalc_trade_from_orders()` 用旧百分比把止损重新锚到新均价 | 硬止损移到 `custom_exit`，框架只留 -0.8 兜底      |
| 实盘 0 单、回测正常           | ZigZag 初始化依赖低波动                                     | 状态机重写后不再依赖首根 K 线                     |
| UI 有信号但不下单             | `process_only_new_candles=True` 中途清空信号               | 设为 `False`（见 6.1）                           |

### 6.1 云服务器「有信号但不下单」诊断记录（2026-08-11）

**现象：** 云服务器 dry-run 模式下，FreqUI 能看到入场信号标注，但 `trades` 表一直为 0。

**根因：** freqtrade 默认 `process_only_new_candles = True`——每根 K 线只在出现瞬间计算一次指标和入场信号，之后的整根 K 线生命周期内，`remove_entry_exit_signals` 会把信号列清零。本策略靠收盘价穿越斐波那契线触发入场：

```
(close < fib_dn_382) & (close.shift(1) >= fib_dn_382.shift(1))
```

穿越点出现在 K 线中途的概率远大于恰好在收盘瞬间，中途穿越时下单逻辑读到的缓存信号已经是 0。

**修复：** 显式设置 `process_only_new_candles = False`，让每 5 秒的处理循环在 K 线中途也重算指标与信号。

**已验证排除的两个误判：**

1. `remove_entry_exit_signals` 不会污染缓存——`analyze_pair` 传入的是 DataFrame 副本。
2. 配置优先级 `config > strategy > default`，服务器 `config_cloud.json` 的 `order_types: market` 本来就覆盖了策略默认值。

**判断修复是否生效：** 看 `orders` 数是否 > 0，而不是「是否有信号」——行情太安静时本来就不会有信号。

## 七、运行方法

```bash
# 回测（重跑时加 --cache none，否则会复用上次结果）
freqtrade backtesting -s FibMartingaleStrategy \
    -c user_data/config/config_all.json \
    --timerange 20260101-20261031 --fee 0.0005 --cache none

# 模拟盘
freqtrade trade -s FibMartingaleStrategy \
    -c user_data/config/config_all.json --dry-run
```

> `--cache none` 很重要：同参数重复回测时 freqtrade 会直接复用缓存结果，改了代码却看不到变化。

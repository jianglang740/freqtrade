# 策略池

**一个策略一个目录**，目录里装这个策略的全部东西：原始设想、每一轮研究报告、研究脚本、产物。
回看一个策略只需要开一个目录。

## 目录约定

新研究一个策略就照这个骨架建：

```
策略池/<策略名>/
├── README.md        阅读入口：一句话结论 + 阅读顺序 + 已定死的结论
├── 01_原始设想.md    动手之前写死：规则、因子定义、要测的变体
├── 02_…md 起        每一轮研究一份报告，编号就是阅读顺序
├── scripts/         研究脚本（可重跑）
└── out/             脚本产出的 csv 明细（派生物，不进 git）
```

三条规矩，是为了防止再出现「东西散在两个文件夹、回看不知道从哪读」：

1. **编号即顺序**。`01_` 永远是原始设想（先想后做，不是先做后编故事），之后的编号按时间追加，
   不回头插号、不重排。
2. **结论被推翻就写在开头，不删旧报告**。旧报告标一行「本文件数字已被 0X 修正」，
   保留下来看清思路是怎么变的。横截面动量那份 [02](横截面动量/02_验证_V0-V7.md) 就是这样。
3. **README 只写结论，不写过程**。过程在编号报告里，避免同一件事在三个地方各说一遍、之后对不上。

## 与别处的关系

| 位置 | 放什么 | 不放什么 |
|---|---|---|
| `策略池/<策略>/` | 策略的想法、研究报告、研究脚本 | 实盘策略源码、数据 |
| [`user_data/strategies/`](../user_data/strategies/) | **实盘/回测用的 `.py` 策略文件，唯一家** | —— |
| [`面板数据/`](../面板数据/) | 数据面板 + 数据工具（构建/读取/抓取） | 任何单个策略的研究脚本 |

⚠️ **不要在 `策略池/` 里放策略 `.py` 的副本**。freqtrade 只加载 `user_data/strategies/` 里的，
副本改了两边不同步，会踩「改了代码没生效」的坑 —— 之前 `Supertrend.py` / `hlhb.py`
就在这里躺了两份逐字节相同的副本，已删除。

⚠️ **一次性的、只服务某一个策略的数据处理脚本，跟着策略走**（`<策略>/scripts/`）；
能被多个策略复用的才进 `面板数据/`。

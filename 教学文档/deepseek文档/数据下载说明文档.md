## 一、数据存储位置与格式

### 存储路径

```
user_data/data/
└── binance/                          ← 交易所名称
    ├── futures/                      ← 交易模式（合约）
    │   ├── BTC_USDT_USDT-5m-futures.feather
    │   ├── BTC_USDT_USDT-1h-funding_rate.feather
    │   ├── BTC_USDT_USDT-1h-mark.feather
    │   └── ...
    └── spot/                         ← 现货数据（如果使用现货模式）
```

### 文件命名规则

```
{交易对}_{时间周期}-{数据类型}.feather
 BTC/USDT:USDT-5m-futures.feather
 │             │   │       └── 存储格式
 │             │   └── 数据类型
 │             └── K线周期
 └── 交易对（/ 和 : 替换为 _）
```

### 数据类型说明

| 类型 | 文件名后缀 | 内容 | 仅合约 |
|------|-----------|------|:--:|
| **K线（价格）** | `-futures` | OHLCV（开高低收量） | |
| **标记价** | `-mark` | 标记价格（用于计算未实现盈亏） | ✅ |
| **资金费率** | `-funding_rate` | 资金费率历史（多空持仓费） | ✅ |

### 存储格式

freqtrade 使用 **Feather** 格式（Apache Arrow 的二进制格式）：

| 特性 | 说明 |
|------|------|
| 读写速度 | 极快（比 CSV 快 10-100 倍） |
| 磁盘占用 | 比 JSON 小，比 Parquet 稍大 |
| 可读性 | 二进制，不可直接文本查看 |
| 跨语言 | Python / R / Julia 均可读取 |

配置中可切换格式：

```json
{
    "dataformat_ohlcv": "feather",   // feather / json / parquet
    "dataformat_trades": "feather"
}
```

## 二、数据下载命令

### 基本命令

```bash
freqtrade download-data -c config.json -t 周期 -p 交易对 --timerange 起止日期
```

### 参数说明

| 参数 | 含义 | 示例 |
|------|------|------|
| `-c` / `--config` | 配置文件 | `-c user_data/config/config_all.json` |
| `-t` / `--timeframes` | K线周期，可多个 | `-t 5m 15m 1h` |
| `-p` / `--pairs` | 交易对，可多个 | `-p BTC/USDT:USDT ETH/USDT:USDT` |

### 时间周期对照表

| 代码 | 含义 | 多少分钟 | 用途 |
|------|------|:--:|------|
| `1m` | 1 分钟 | 1 | 高频策略、精细回测 |
| `3m` | 3 分钟 | 3 | FreqAI 短周期 |
| `5m` | 5 分钟 | 5 | 常用策略回测 |
| `15m` | 15 分钟 | 15 | 中频策略 |
| `1h` | 1 小时 | 60 | 趋势判断、@informative 大周期 |
| `4h` | 4 小时 | 240 | 主趋势参考 |
| `1d` | 日线 | 1440 | 长期趋势 |

### 实际示例

```bash
# 下载 BTC 和 ETH 的 5 分钟数据，最近 3 个月
freqtrade download-data \
    -c user_data/config/config_all.json \
    -t 5m \
    -p BTC/USDT:USDT ETH/USDT:USDT \
    --timerange 20260501-20260807

# 同时下载多个周期
freqtrade download-data \
    -c user_data/config/config_all.json \
    -t 1m 5m 15m 1h \
    -p BTC/USDT:USDT

# 不指定交易对，读取配置文件中的白名单
freqtrade download-data -c user_data/config/config_all.json -t 5m

# 不指定时间范围，下载最近 30 天
freqtrade download-data -c user_data/config/config_all.json -t 5m -p BTC/USDT:USDT
```

## 三、三种下载模式

freqtrade 的数据下载有**增量追加**、**前置补充**和**全量替换**三种模式。

### 3.1 增量追加（默认）

**行为：** 只下载本地缺失的最新数据，追加到已有文件。

```bash
freqtrade download-data -t 5m -p BTC/USDT:USDT
```

**原理：**
1. 读取本地文件最后一根K线的时间戳
2. 向交易所请求从该时间戳至今的K线
3. 将新数据 `pd.concat` 到旧 DataFrame 后面
4. 覆盖写入文件

**场景：** 日常更新数据。每天跑一次，只拉前一天到现在的新 K 线，秒级完成。

### 3.2 前置补充（`--prepend`）

**行为：** 在已有数据前面补充更早的历史数据。

```bash
freqtrade download-data -t 5m -p BTC/USDT:USDT --timerange 20260101-20260501 --prepend
```

**原理：**
1. 读取本地文件第一根K线的时间戳
2. 向交易所请求该时间戳之前的指定时间范围
3. 将新数据拼到旧 DataFrame 前面
4. 覆盖写入文件

**场景：** 现有数据从 5 月开始，想往前补到 1 月。

### 3.3 全量替换（`--erase`）

**行为：** 删除本地所有相关数据，从头重新下载。

```bash
freqtrade download-data -t 5m -p BTC/USDT:USDT --timerange 20260501-20260807 --erase
```

**原理：**
1. 删除本地所有匹配的 `.feather` 文件
2. 从交易所请求指定时间范围的完整数据
3. 写入新文件

**场景：** 数据乱了、换策略周期、出现数据缺失。

> ⚠️ `--erase` 会删除**同一交易对、同一周期的所有数据类型**（包括 funding_rate 和 mark 数据）。

### 模式对比

| 模式 | 本地已有数据 | 新数据位置 | 速度 |
|------|:--:|------|:--:|
| 默认（增量） | 保留 | 追加到末尾 | 快（只拉增量） |
| `--prepend` | 保留 | 插入到开头 | 慢（拉历史大段） |
| `--erase` | **删除** | 全量替换 | 最慢（完整重拉） |

## 四、数据增量机制

### 内部工作流程

```
freqtrade download-data
  │
  ├── 1. 确定要下载的 pair × timeframe 组合
  │
  ├── 2. 对每个组合：
  │     │
  │     ├── 2a. 检查本地是否有已有数据文件
  │     │     ├── 有 → 读取最后一行的时间戳 → 设为 since
  │     │     └── 无 → since = timerange 起始（或默认 30 天前）
  │     │
  │     ├── 2b. 调用 exchange._async_get_historic_ohlcv()
  │     │     向交易所 REST API 分页请求 (since, now] 的数据
  │     │     每次请求最多 1000 根（交易所限制）
  │     │
  │     ├── 2c. 将原始 OHLCV 列表转为 DataFrame
  │     │
  │     ├── 2d. 如果已有旧文件：
  │     │     pd.concat([old_df, new_df]).drop_duplicates(subset=['date'])
  │     │     └── 自动去重同一时间戳的K线
  │     │
  │     └── 2e. 写入 .feather 文件
  │
  └── 3. 完成
```

### 关键行为

| 行为 | 说明 |
|------|------|
| **自动去重** | 同一时间戳的K线只会保留一份 |
| **断点续传** | 中断后重新运行，`since` = 最后一条已有数据的时间，不会重复下载 |
| **分页拉取** | 每次 API 请求最多 1000 根K线，大时间范围自动分多次请求 |
| **并行下载** | 多个交易对同时下载（asyncio 并发） |
| **完整性检查** | 自动检测数据缺口，必要时补拉 |

### 不需要手动管理数据

一旦下载了数据，后续只需：

```bash
# 每天或每周跑一次
freqtrade download-data -c config.json -t 5m
```

框架会自动：
1. 发现本地已有数据
2. 确定最后更新时间
3. 只拉最新的增量
4. 去重合并
5. 更新文件

## 五、合约数据特殊性

### 为什么合约需要三类数据？

```
K线（futures）
  └── 开了、高了、低了、收了、量了
      → 策略指标计算、信号生成

资金费率（funding_rate）
  └── 每 8 小时一次，多头付费给空头（或反之）
      → 计算持仓成本
      → 影响做多 vs 做空的盈亏

标记价（mark）
  └── 交易所计算的"公允价值"
      → 用于计算未实现盈亏
      → 更准确地判断是否达到止盈/止损条件
```

### 下载合约数据的完整命令

```bash
freqtrade download-data \
    -c user_data/config/config_all.json \
    -t 5m 1h \
    -p BTC/USDT:USDT ETH/USDT:USDT \
    --timerange 20260501-20260807
```

> 注意交易对格式是 `BTC/USDT:USDT`（合约），不是 `BTC/USDT`（现货）。

你会看到三种文件被自动下载：

```
BTC_USDT_USDT-5m-futures.feather        ← K线
BTC_USDT_USDT-1h-funding_rate.feather   ← 资金费率
BTC_USDT_USDT-1h-mark.feather           ← 标记价
```

资金费率和标记价总是以 **1h 周期**下载（交易所规定），即使用 `-t 5m` 也会连带下 1h 的这两类数据。

### 现货不需要这些

现货模式只有 `-futures` 文件，没有 `funding_rate` 和 `mark`。

## 六、命令速查

### 查看已有哪些数据

```bash
freqtrade list-data -c user_data/config/config_all.json
```

输出示例：
```
Found 2 pairs with 3 timeframes:
pair          timeframe   type         
BTC/USDT:USDT 5m          futures
BTC/USDT:USDT 1h          futures
BTC/USDT:USDT 1h          funding_rate
BTC/USDT:USDT 1h          mark
ETH/USDT:USDT 5m          futures
ETH/USDT:USDT 1h          futures
ETH/USDT:USDT 1h          funding_rate
ETH/USDT:USDT 1h          mark
```

### 查看数据文件占用

```bash
du -sh user_data/data/binance/
```

### 清理特定交易对的数据

```bash
rm user_data/data/binance/futures/ADA_*
```

### 典型场景命令

```bash
# 场景 1：首次下载（全量）
freqtrade download-data -c config.json -t 5m 1h -p BTC/USDT:USDT ETH/USDT:USDT --timerange 20260101-20260801

# 场景 2：每日更新（增量）
freqtrade download-data -c config.json -t 5m 1h

# 场景 3：补充更早数据（往前补）
freqtrade download-data -c config.json -t 5m -p BTC/USDT:USDT --timerange 20250101-20260101 --prepend

# 场景 4：数据出问题了（重来）
freqtrade download-data -c config.json -t 5m -p BTC/USDT:USDT --timerange 20260501-20260807 --erase

# 场景 5：切换新周期（先全量下载）
freqtrade download-data -c config.json -t 15m -p BTC/USDT:USDT --timerange 20260101-20260801
```

### 自动化更新脚本

```bash
#!/bin/bash
# update_data.sh — 放到 crontab 每天执行

source /opt/anaconda3/etc/profile.d/conda.sh
conda activate freqtrade
cd /path/to/freqtrade

ssh -fN quant-proxy 2>/dev/null
sleep 3

freqtrade download-data -c user_data/config/config_all.json -t 1m 5m 1h
```

crontab 配置（每天凌晨 2:00）：
```
0 2 * * * /path/to/freqtrade/update_data.sh >> /path/to/freqtrade/user_data/logs/data_update.log 2>&1
```

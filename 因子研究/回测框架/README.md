# 因子回测框架

跑在**两套面板**上的加密货币单因子回测：

- **因子数据**：`因子研究/因子数据/panels/{market}_{tf}.parquet`（`date / symbol / <因子>` 长表）
- **行情数据**：`因子研究/行情数据/` 数据湖（K 线 + 资金费率 + 符号主表）

方法沿用 `../../fct_backtest/code/fct_backtest改进版.py`（全 A 股单因子框架）的四项核心：
每日截面 MAD 去极值 + Z 分数、日历化调仓、Fama-MacBeth + Newey-West、风格中性化。
**执行层全部按币圈重写** —— 那才是股票框架不能直接用的部分。

## 二、快速开始

```bash
# 最简：现货日线，30 日动量，每日调仓，持 1/5/10/20 天
python 因子研究/回测框架/run_backtest.py --factor mom_30d

# 永续合约 + 周频调仓 + 扣资金费（默认就扣）
python 因子研究/回测框架/run_backtest.py --market um --factor mom_30d --rebalance weekly

# 月频调仓、只看多头、成交额加权
python 因子研究/回测框架/run_backtest.py --market um --factor vol_30d \
    --rebalance monthly --mode long_only --weighting adv

# 小时线（一定带 --start，否则从 2017 年读起很慢）
python 因子研究/回测框架/run_backtest.py --tf 1h --factor mom_168h \
    --rebalance daily --start 2024-01-01 --hold 1,24

# 只跑统计不出图（批量扫因子时用）
python 因子研究/回测框架/run_backtest.py --factor mom_90d --no-plots --tag mom90_spot
```

产物默认写到 `out/<因子_市场_周期_调仓>/`，用 `--tag` 覆盖目录名。

**前置条件**：因子面板已生成（`因子研究/因子数据/build_factors.py`）。
面板里没有的因子会直接报 `KeyError` 并列出可用因子名。

## 三、一次回测的时间轴（无前视）

```
T  根 bar 收盘        → 因子已知（面板里的值只用 ≤ T 的数据算出来）
T  日收盘后           → 用当日截面定权重
T+1 根 bar 开盘       → 建仓（--exec-price open，默认）
T'  下一个调仓日      → T'+1 根 bar 开盘平仓
窗口收益 = 平仓价 / 建仓价 - 1
```

三处容易错位的地方，代码里都写死了：

1. **建仓价表的索引仍然是信号日**（`align_entry_prices`）。值取下一根 bar 的价格，
   但索引不换成建仓日 —— 否则下游会拿 T+1 收盘的因子去解释 T+1 开盘的成交，就是前视。
   这个 bug 曾经让年化收益虚高到 2927%、夏普 74。
2. **股票池用「上一根日线的状态」**（`build_universe` 里 `reindex→ffill`），盘中不改池。
3. **风格因子（ADV/Beta/波动）在日线上滚动，然后 ffill 到调仓日**，不跨期回填。

## 四、参数

| 参数 | 默认 | 说明 |
|---|---|---|
| `--market` | `spot` | `spot` 现货 / `um` U 本位永续（只有 um 扣资金费） |
| `--tf` | `1d` | `1d` / `1h` |
| `--factor` | `mom_30d` | 因子面板里的列名 |
| `--factor-panel` | 空 | 读**项目自建**的因子面板（`date/symbol/<因子>` parquet），不填则读公共因子库 |
| `--start` `--end` | 全历史 | UTC，**左闭右开** |
| `--rebalance` | `daily` | `daily` / `weekly` / `monthly` / `every`（每 N 根 bar） |
| `--every` | 1 | `rebalance=every` 时的 N |
| `--hold` | `1,5,10,20` | 持有几个**调仓窗口**，不是自然日 |
| `--quantiles` | 5 | 截面分几组 |
| `--direction` | `long_top` | `long_top` 做多因子高值；`short_top` 反过来（做反转） |
| `--mode` | `long_short` | `long_short` / `long_only` / `short_only` |
| `--weighting` | `equal` | `equal` / `adv`（成交额加权）/ `vol_inv`（逆波动） |
| `--gross-leverage` | 1.0 | 多空合计毛敞口，多空模式下每腿 = 该值 / 2 |
| `--top-n` | 100 | 每日池子上限（按 14 日日均成交额排名） |
| `--adv-min` | 1e6 | 日均成交额下限（美元） |
| `--min-history` | 30 | 上市不足 N 天不进池 |
| `--exec-price` | `open` | `open` 次日开盘 / `close` 次日收盘 |
| `--fee-bps` | 现货 10 / 永续 5 | 单边手续费 |
| `--slippage-bps` | 2 | 单边滑点 |
| `--delist-shock` | 0 | 撞退市时**额外**扣的亏损（0 = 按最后可成交价平仓） |
| `--no-funding` | 关 | 永续不扣资金费 |
| `--neutralize` | `logadv_beta` | `None` / `logadv` / `logadv_beta` / `logadv_beta_vol` |
| `--mad-n` | 5.2 | MAD 去极值倍数 |
| `--min-obs` | 20 | 单期截面最少符号数（分组 / IC） |

## 六、和股票框架的差异（**这是重点**）

| 环节 | 股票框架 | 这里 | 为什么必须改 |
|---|---|---|---|
| 成交时点 | T+1 **收盘** | T+1 **开盘**（可切） | 币圈 24/7 连续，次日开盘就是第一可成交价 |
| 年化 | 252 个交易日 | **365** 天，按真实日历天数算 | 没有休市、没有周末 |
| 方向 | 只能做多，算多空价差 | **真建多空组合** | 永续合约直接做空，空头还能收资金费 |
| 成本 | 不考虑 | 换手 × (手续费 + 滑点)，逐窗口扣 | 币圈换手极高，这是最致命的偏差 |
| 资金费 | 无 | 逐窗口按实际结算累计扣/收 | 多空组合的空头每年能收 10~20% |
| 退市 | `is_st` / `delist_date` 缺失 | 持仓撞上退市 → 最后可成交价平仓 + 可配 `delist_shock` | 归档里有 235 个已下架币 |
| 中性化 | 市值 + 行业 | **流动性(size) + BTC Beta (+波动率)** | 币圈没有行业；共同风险是 Beta，所有币跟 BTC 同涨同跌 |
| 加权 | 等权 | 等权 / 成交额 / 逆波动 | 小币流动性差异比 A 股大一个数量级 |
| 分组 | `pd.qcut` | `ceil(rank/count*n)` | 币圈大量价格并列（横盘到小数点后 8 位），qcut 会丢组 |
| 极值 | 全样本 MAD | **逐日截面 MAD + 逐期缩尾** | 币圈 20 天 ±300% 是常态，全样本统计量会把未来漏进来 |

保留不变的四项：**每日截面去极值/标准化**、**日历化调仓**、
**Fama-MacBeth + Newey-West**、**风格中性化后看残差还有没有 IC**。

## 七、几个必须知道的口径

### 7.1 重叠持有 ≠ 重复复利

`--hold 5` 不是「持有一个 5 日收益序列」，而是 **5 个错位子组合各占 1/5 资金**
（`_smooth_weights`）。直接把重叠窗口的远期收益连乘会重复复利，
股票框架在这上面踩过坑，这里直接用逐窗口真实组合收益，并丢掉前 h-1 个未铺满的窗口。

### 7.2 资金费按「每次结算」累计，不是按年化费率

`因子研究/行情数据/um/funding/` 存的是每次结算的费率（`funding_rate`，8 小时一次居多，
`funding_interval_hours` 记录间隔）。`funding_delta` 把每个符号的费率**累加**，
窗口内 `Σ rate × 权重` 就是该窗口的资金费支出。
所以「年化资金费 20%」是算出来的结果，不是输入的假设。

> 踩过的坑：归档的 fundingRate CSV 是三列 `calc_time, funding_interval_hours, last_funding_rate`。
> 早期解析只读了两列，把 interval（1/4/8）当成了费率，回测里算出年化 22 万%。

### 7.3 破产保护

净值 ≤ 0 时年化收益直接给 −1（−100%）、最大回撤封在 −1，并在汇总表里打「破产」标记。
否则 `(末值/初值)^(365/天数) - 1` 会对负数开方，得到复数并抛 `TypeError`。

### 7.4 统计用缩尾远期收益，组合用真实收益

IC 是秩相关，不怕极端值；但 **FM 回归和分位平均远期收益**会被一两个百倍币绑架，
所以这两处用逐期 1%/99% 缩尾后的远期收益（`stats.winsorize_rows`）。
**组合模拟仍然用真实收益** —— 你真的会持有那只币，不能假装它只涨了 300%。

### 7.5 现货的多空是「理论价差」

`--market spot --mode long_short` 会照常建多空组合，但**现货做不了空**，
那条曲线只是多空价差，不是可交易策略。现货只能 `--mode long_only`；
真正能双边的只有 `um`（永续）。

### 7.6 退市

持仓期间该币不再有 bar：用最后一个可成交价平仓，`dead_exits` 计数。
`--delist-shock 0.3` 表示额外再扣 30% —— 真实退市往往更惨（流动性归零），
默认 0 是保守（对策略有利）的口径，报告里必须写清楚用的是哪个。

## 八、已知限制

1. **只有 USDT 计价、只有日线与小时线**。5m/1m 没拉（体积会从 1.4 GB 涨到 100 GB+）。
2. **没有行业中性化**，用 Beta 代替。币圈的板块（DeFi / L2 / Meme）相关性很强，
   但目前没有可用的点时板块分类表，`logadv_beta` 只能剥离一部分共同风险。
3. **资金费只用于扣成本，没有做成因子**。
4. **滑点是固定 BPS**，没有按盘口深度建模。小币的实际冲击远大于 2bp，
   所以 `--slippage-bps` 建议在 top_n 较小时调高（20~50）做敏感性。
5. **容量没算**。ADV 加权 + `--gross-leverage` 起来的组合规模要自己乘一遍，
   池子里排第 80 的小币可能只吃得住几万美元。
6. **幸存者偏差已处理**：股票池走数据湖的完整符号表（含已下架），
   不是「今天还活着的币」——但归档本身只从 2017/2019 年开始，
   更早上线的币的早期数据拿不到。

## 九、示例结果（2026-11-06 实测，用于确认口径，不是投资建议）

`mom_30d` / `um` / 周频 / top80 / 中性化 `logadv_beta` / 持有 1 和 4 周：

| 持有 | IC | IC_t_NW | 年化 | 波动 | 夏普 | 最大回撤 | 年化成本 | 年化资金费 |
|---|---|---|---|---|---|---|---|---|
| 1 周 | −5.19% | −4.95 | 16.91% | 40.72% | 0.42 | −40.21% | 3.14% | +14.37% |
| 4 周 | −5.41% | −3.50 | −0.31% | 33.85% | −0.01 | −47.08% | 1.47% | +10.05% |

同期 BTC 买入持有：累计 +889.9% / 年化 39.9% / 最大回撤 −76.7% / 夏普 0.66。

> **资金费那一列是「正 = 收到」**，不是成本。这个组合的净收益里有一大块来自空头收到的
> 资金费（2023 年后尤其明显），而不是因子本身 —— 见 §7.2。不扣资金费的同一组回测
> 年化只有 3.91% / −7.70%。看结论时这两列必须并排。

**读法**：IC 稳定为负且 t 值显著 —— 30 日动量在币圈横截面上是**反转**而不是延续，
`--direction short_top` 才对应「做多跌得多的」。但扣完成本后多空组合几乎不赚钱，
说明这个信号在 top80 这个流动性池子里已经被套利掉了。**这是一个诚实的否定结果**，
不要拿它当策略。
